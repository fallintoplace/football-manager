# Touchline analytics service

This service receives matchdays from the Touchline simulator, turns the match, event, replay, rating, standings, player-snapshot, run, club-match, and player-match streams into Arrow tables, and appends them to ClickHouse and Iceberg.

From this directory, run `go run .` after the local stack is available. From the project root, `docker compose up --build` starts ClickHouse, MinIO, the Iceberg REST catalog, and the service on port 8787.

ClickHouse 26.2 exposes ClickStack at `http://localhost:8123/clickstack`. Touchline creates one stable `run_id` per career and season, shows it in the Analytics Lab, and sends it with every matchday. Replace `replace-with-run-id` and `replace-with-club-id` in `clickstack-queries.sql` with the displayed values, then use the queries as ClickStack charts for the season story, final table, points race, xG trend, player development, event volume, and replay density. The frontend reads the same round-level dataset from `/api/analytics/timeline`. The custom pitch heatmap remains in Touchline, where the replay canvas can render spatial bins directly.

The contract-v2 facts live in `touchline_runs_v2`, `touchline_match_club_facts_v2`, and `touchline_player_match_facts_v2`. Run metadata is available from `GET /api/analytics/runs`. Club-match facts preserve the simulator's tactical ledger and both teams' tactic settings; player-match facts preserve starts, minutes, ratings, shots, goals, and event xG. Existing ingested matches are automatically backfilled when the new fact tables are missing, without rewriting their Iceberg snapshot.

The structured event feed lives in `touchline_match_actions_v2` and the Iceberg `match_actions` table. Each action has a player ID, optional recipient, possession and sequence IDs, period/second, coordinates, outcome, and JSON qualifiers. Narrative highlights remain in `touchline_match_events_v2`; use `action-lab.sql` for possession chains, pass networks, shot context, and spatial action bins.

Action-derived manager insights are available from `GET /api/analytics/action-insights?run_id=...&club_id=...`. The endpoint reads the action table directly to calculate possession volume, pass completion, progressive passing, shot xG, action mix, repeat passing connections, and a lightweight analyst finding for the current game plan.

The same response includes a player action profile with a primary role inferred from the evidence: build-up hub, progressive creator, progressive carrier, final-third connector, box threat, pressing winner, or connector. The role is deliberately derived from observed actions rather than a static player label.

The Real Data Lab is separate from the simulator tables. Run `node scripts/import-statsbomb.mjs --limit=20` after starting the stack to fetch a deterministic 20-match 2015/16 Premier League slice from StatsBomb Open Data and send it to `POST /api/analytics/real-data/import`; use `--match-id=3754217` for one fixture. The importer normalizes StatsBomb's 120x80 coordinates to 0-100, preserves source player/team names, and records the source event and coordinate system in JSON qualifiers. Real rows land in `touchline_real_matches_v1`, `touchline_real_actions_v1`, Iceberg `real_matches`, and Iceberg `real_actions`. The read APIs are `GET /api/analytics/real-data/matches?source=statsbomb&season=2015` and `GET /api/analytics/real-data/match?source=statsbomb&source_match_id=3754217`; the Analytics tab uses both to provide a match selector, shot map, pass links, and player profiles. Use `real-data-lab.sql` in ClickStack to compare action mix, player involvement, shot locations, and passing connections. The raw event files are not vendored into this repository; the source is fetched at import time and should be attributed as StatsBomb Open Data.

The World Cup 2026 Lab imports the public-domain [openfootball/worldcup.json](https://github.com/openfootball/worldcup.json) snapshot with `node scripts/import-worldcup2026.mjs`. It writes match facts to `touchline_worldcup_2026_matches_v1` and goal facts to `touchline_worldcup_2026_goals_v1`, plus Iceberg `worldcup_2026_matches` and `worldcup_2026_goals`. The API is `GET /api/analytics/worldcup-2026/overview`; the Analytics tab visualizes the tournament footprint, group tables, top scorers, goal timing, venues, and knockout bracket. Use `worldcup-2026-lab.sql` for ClickHouse footprint, scorer, timing, venue, and `EXPLAIN indexes = 1` experiments.

Career archive data is available from `GET /api/analytics/season-comparison?career_id=...&club_id=...`. It joins the run registry to final standings, club-match facts, opponent xG, player minutes, and tactical averages so the same career can be compared across seasons. `career-comparison.sql` contains the equivalent ClickHouse query for a ClickStack chart or a query-log experiment.

Tactical matchup data is available from `GET /api/analytics/tactical-matchup?run_id=...&club_id=...&opponent_id=...`. Omit `opponent_id` to compare every opponent in the run. The query self-joins the club-relative fact table so each row compares both teams' shapes, mentality, pressing, xG, box entries, press wins, counters, and build-up failures. `tactical-matchup.sql` is the paste-ready ClickStack version.

Iceberg snapshot history is available from `GET /api/analytics/iceberg/history?table=player_match_facts`. The endpoint exposes snapshot IDs, parent lineage, sequence numbers, timestamps, and operation summaries from the REST catalog; the Analytics Lab surfaces the current snapshot count.

Use `contract-v2.sql` with the same run ID to validate the grain, reconcile club facts with `touchline_matches_v2`, calculate player xG per 90, and compare tactical identities. The file is intentionally small enough to run after each schema change.

The ClickHouse learning lab is in `performance-lab.sql`. The analytics schema creates `touchline_club_round_metrics` with a `SummingMergeTree` and `touchline_club_round_metrics_mv`; the view handles new match inserts, while the lab uses an explicit run-scoped backfill for existing facts. The file compares raw and materialized results, captures `system.query_log` metrics, runs `EXPLAIN indexes = 1`, and inspects `system.parts`, `system.merges`, and `system.columns`.

`scale-lab.sql` safely replaces only the `scale-lab-*` slice with 20 deterministic copies of one stored season, then measures insert cost, raw versus materialized reads, parts, merges, and column types. `clickstack-alerts.sql` is the xG-underperformance SQL for ClickStack alerting; the local 26.2 UI currently advertises alerts as unavailable, so the query is kept version-independent and ready to paste into a newer ClickStack deployment.

ClickHouse repairs incomplete match facts before marking a match ingested. Iceberg writes are run-aware and overwrite the `(run_id, season, round)` slice on retry, so a failed multi-table append can be replayed without duplicating a round. The `_v2` ClickHouse fact tables keep the old local schema isolated while new data uses run-aware sorting keys.
